# Предиктор задержек городского транспорта

Система раннего предупреждения для диспетчера. Она принимает телематику NDTP,
накладывает её на нитку графика и **за 10–15 минут до события** прогнозирует
отклонение на остановке. К каждому прогнозу прилагаются интервал и вероятность
опоздания, предполагаемая причина и участок маршрута. Всё это выводится на
дашборд: карта, «светофор» риска, карточки инцидентов, what-if.

| Модуль | Контейнер | Порт |
|---|---|---|
| ML-ядро (CatBoost + PyTorch/ONNX, дообучение) | `ml` | 8001 |
| Backend (приём NDTP, сопоставление, алерты, REST/WS) | `backend` | 8000, NDTP 9201 |
| Диспетчерский BI-дашборд (nginx + SPA) | `dashboard` | 8080 |
| Проигрыватель исторического потока → NDTP | `replayer` | 8090 |
| Эмулятор организаторов (опционально) | `emulator` | 18080 |

## Быстрый старт

```bash
docker compose up -d --build
```

Датасет уже находится в `data/dataset`. Если он расположен отдельно, задайте
`DATASET_DIR=/абсолютный/путь/к/dataset` в `.env` (см. `.env.example`) перед запуском.
Если порт 8080 занят, задайте, например, `DASHBOARD_PORT=8081` в `.env` и откройте
дашборд на <http://localhost:8081>.

На проверенной машине сборка с нуля заняла около 5 минут (образ ML — 2,73 ГБ).
После `up` первый прогноз появился примерно через 9 секунд, все сервисы стали
`healthy` примерно через 25 секунд; проверить их состояние можно через
`docker compose ps`. Время зависит от машины и наличия базовых образов.

* Дашборд: <http://localhost:8080> (порт меняется через `DASHBOARD_PORT`). Поток из
  датасета стартует сам: ×10, с 06:30, перед этим 20 минут прогрева.
* Swagger: backend <http://localhost:8000/docs> · ML <http://localhost:8001/docs> ·
  replayer <http://localhost:8090/docs>.
* Документация (Sphinx + OpenAPI): <http://localhost:8080/docs-site/>.
* Сабмит v7, для которого команда сообщила score 1.00000:
  [`artifacts/submission-v7.csv`](artifacts/submission-v7.csv).
  [`artifacts/submission.csv`](artifacts/submission.csv) — результат исходного ансамбля.

## Инструкция для жюри

**1. Подать поток из исторического датасета.** Replayer запускается автоматически.
Скорость и время старта меняются на дашборде в окне «Поток» (кнопка в шапке) или через API:

```bash
curl -X POST localhost:8090/api/start -H 'Content-Type: application/json' \
     -d '{"speed": 30, "start_time": "07:00", "warmup_min": 20}'
```

**2. Подать поток с эмулятора NDTP организаторов.**

Архив образа эмулятора предоставляется отдельно и не входит в репозиторий:

```bash
docker load -i /путь/к/ndtp-telemetry-emulator.tar
make emulator
curl -X POST localhost:18080/api/config -H 'Content-Type: application/json' -d '{
  "targetHost": "backend", "targetPort": 9201,
  "units": [{"unitId": 1166336, "intervalMs": 2000, "autoGenerate": true, "cells": []}]}'
```

У терминалов эмулятора нет расписания. Система проверяет handshake и CRC,
разбирает навигацию, скорость и другие поддерживаемые ячейки. Ячейки дверей
Irma04 и Crown03 распознаются, но их поля не разбираются; эмулятор передаёт их
с фиксированными значениями. Терминалы видны на карте с отметкой «без расписания».

**3. Где смотреть прогнозы и алерты.**

| Что | Где |
|---|---|
| Карта, инциденты, схема рейса, what-if | дашборд <http://localhost:8080>, вкладка «Мониторинг» |
| Качество прогноза, производительность, проблемные участки, журнал инцидентов | дашборд, вкладка «Аналитика» |
| Снимок состояния / алерты (JSON) | `GET /api/state`, `GET /api/alerts` на :8000 |
| Горизонт и онлайн-качество | `GET /api/metrics` → `online.horizon_ok_share`, `retro_predictions`, `mae_s` |
| Латентность ML | `GET :8001/metrics` |

**4. Проверить деградацию.** Выполните `docker compose pause replayer` или
`docker compose stop ml`. В первом случае система переходит на последнее известное
состояние, во втором — на fallback без ML. Дашборд показывает баннер. Для
восстановления выполните соответственно `docker compose unpause replayer` или
`docker compose start ml`. Пауза сохраняет текущую позицию исторического потока.

## Если что-то не запускается

* `all predefined address pools have been fully subnetted`: в Docker закончились
  подсети. Запускайте с явной подсетью:
  `COMPOSE_FILE=docker-compose.yml:compose.subnet.yml docker compose up -d --build`.
  Адрес подсети можно поменять через `COMPOSE_SUBNET`.
* Нет датасета: задайте `DATASET_DIR` (см. `.env.example`). Сервисы `backend` и
  `replayer` читают из него план (`validate/schedule_plan.csv`) и поток
  (`validate/traffic.csv`).


## Модель v7: результат платформы 1.00000

Команда сообщила score **1.00000** для [submission-v7.csv](artifacts/submission-v7.csv).
Это нормированная оценка платформы, не нулевая ошибка. Сохранены точные веса
ансамбля **80% residual CatBoost + 20% исходная GRU** и отдельный офлайн-вход.
[Воспроизведение, обучение residual-компонента и ограничения](docs/platform-v7.md).
Локальная MAE v7 — **66.16 с**; её рост на платформе не доказывает перенос на новые дни.
Онлайн-модель и исходный ансамбль ниже описаны отдельно.

## Результаты исходной модели

**Точность.** Модели обучались на train, проверка — на labels_test. Утечки
нейтрализованы (подробности в [docs/ml.md](docs/ml.md)).

| | MAE, с |
|---|---|
| Нулевой прогноз | 103.3 |
| Baseline `cur_dev_s` | 93.4 |
| **Сабмит: CatBoost + GRU** | **65.6** |
| Онлайн без подсказки (из потока) | 75.8 |
| На потоке, replayer (онлайн-MAE / наивный прогноз) | ≈ 70 / ≈ 130 |

**Горизонт.** 100% прогнозов сделаны с упреждением 10–15 минут; прогнозов задним
числом — 0.

**Производительность.** Прогноз ML на пачку из 30 ТС занимает 22 мс (159 мс с
SHAP-объяснениями). Путь от пакета до прогнозов по парку — 75 мс (p50). Трекер
обрабатывает 23 мкс на точку. Подробнее — в
[docs/performance.md](docs/performance.md).

## Реализованные дополнительные возможности

- **Map matching без сети дорог.** GPS сопоставляется с остановками вдоль отрезка
  между точками, с учётом курса движения, физической правдоподобности и конечных
  (прибытие/отправление). Медианная ошибка восстановления факта — 1.3 с.
- **Ансамбль CatBoost + PyTorch.** GRU обрабатывает последовательность телеметрии.
  Инференс идёт через **ONNX Runtime**, граф совпадает с PyTorch.
- **Интервал и вероятность.** Квантильный интервал откалиброван конформно
  (покрытие 80%), классы early/ontime/late дают вероятности.
- **Причина и рекомендации.** Правила по производным признакам (простой, скорость
  на участке, накопленное опоздание, GPS) дополнены SHAP-вкладами модели.
- **Векторная карта.** MapLibre GL на тайлах OpenFreeMap: натуральные цвета, чёткие
  подписи на русском при любом зуме, 3D-здания. Маршруты проложены по дорогам (OSRM),
  автобусы движутся плавно, вдоль линии дороги и с реальной скоростью.
- **Схема рейса.** Для выбранного ТС: пройденная остановка, положение машины,
  остановки по расписанию до цели прогноза и участок под риском.
- **Инцидент «в работе».** Диспетчер отмечает, что взял инцидент; отметка хранится
  в backend (`POST`/`DELETE /api/alerts/{id}/ack`) и попадает в журнал закрытых.
- **What-if на дашборде.** Три сценария: выпуск резервного ТС, сокращение стоянки
  на N секунд, приоритет на светофорах (время хода до цели −N %).
- **Дообучение без остановки.** `POST /v1/train` запускает обучение в фоне, после
  чего модель подменяется на лету.
- **Спецификация NDTP.** Кодек проверяет размеры ячеек и CRC, разбирает
  поддерживаемые типы, отвечает `NPH_RESULT`, принимает `NPH_SND_HISTORY` и
  восстанавливает синхронизацию потока. Неподдерживаемые ячейки сохраняются как raw bytes.
- **Деградация.** Обрывы связи, устаревшие данные и отказ ML не останавливают
  сервис; при перемотке потока состояние сбрасывается.

## Разработка

```bash
uv venv -p 3.12 .venv && uv pip install -p .venv/bin/python -e libs/ndtp -e libs/transit_core \
  -e services/backend -e services/replayer pandas pyarrow catboost onnx onnxruntime fastapi "uvicorn[standard]" httpx pytest
uv pip install -p .venv/bin/python torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pytest -q tests
cd services/ml && PYTHONPATH=. ../../.venv/bin/python -m mlcore.train   # обучение + сабмит
```

Структура: `libs/ndtp` — протокол, `libs/transit_core` — расписание, трекер и
признаки (общие для обучения и онлайна), `services/*` — сервисы, `artifacts/` —
модели и справочники, `docs/` — документация, `scripts/` — справочники,
OpenAPI, бенчмарк. В `artifacts/models/current` лежит модель для потокового сервиса,
в `artifacts/models/platform-v7` — отдельная замороженная модель для конкурсного CSV.
