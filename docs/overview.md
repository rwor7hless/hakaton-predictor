| Модуль | Каталог | Ответственность |
|---|---|---|
| NDTP-кодек и сервер | `libs/ndtp` | разбор NPL/NPH, CRC-16/Modbus, ячейки (Nav00 и др.), asyncio TCP-сервер с ответом `NPH_RESULT` |
| Ядро предметной области | `libs/transit_core` | расписание, онлайн map matching, признаки — **один код** для обучения и онлайна |
| ML-ядро | `services/ml` | обучение, честная валидация, ансамбль, инференс, API, дообучение с горячей заменой |
| Backend | `services/backend` | приём потока, состояние парка, прогнозный цикл, причины, алерты, what-if, REST/WS |
| Replayer | `services/replayer` | проигрывание исторического `traffic.csv` как NDTP-терминалов (по соединению на ТС) |
| Дашборд | `services/dashboard` | диспетчерский BI: карта, светофор риска, карточки инцидентов, метрики |

## Поток данных

1. Терминал (эмулятор или replayer) открывает TCP-соединение, шлёт `NPH_SGC_CONN_REQUEST`,
   затем `NPH_SND_REALTIME`/`NPH_SND_HISTORY` с ячейкой `G6CellNav00`.
2. `NdtpServer` проверяет CRC, разбирает ячейки и передаёт точку в очередь backend.
3. `VehicleTracker` сопоставляет точку с ниткой графика: определяет пройденные
   остановки (медианная ошибка восстановления факта — 1.3 с), ведёт простой, скорость.
4. По часам потока каждые 30 с для каждого ТС выбирается целевая остановка — первая
   с плановым временем в окне `(T+10, T+15]` мин — и считаются признаки только по
   данным `<= T`.
5. ML-ядро возвращает задержку, интервал q10–q90, вероятности опоздания/опережения и
   вклады признаков; backend формирует уровень риска, причины, рекомендации и алерт.
6. Когда ТС проходит целевую остановку, прогноз сверяется с фактом — онлайн-MAE и
   доля прогнозов с горизонтом 10–15 мин считаются непрерывно.

## Геометрия маршрутов и движение на карте

`scripts/build_routes.py` строит для каждого ТС полный оборот по дорогам: перегоны между
соседними остановками прокладываются сервисом OSRM с направлением движения в каждой
точке. Если перегон неправдоподобно длиннее реального GPS-трека (выделенные полосы,
разворотные кольца, недоступные легковому профилю), вместо него берётся сглаженный
реальный трек. Результат — `artifacts/reference/route_geometry.json`: ломаная,
накопленная длина и положение каждой остановки в метрах.

Backend проецирует GPS-точку ТС на участок оборота между последней пройденной и
следующей остановкой (с учётом курса, чтобы не перепутать встречное направление) и
отдаёт `route_m` — метры вдоль маршрута. Дашборд ведёт маркер по линии дороги:
- точки привязаны ко времени GPS-фиксации;
- рендер идёт по восстановленным часам потока с адаптивной задержкой (99-й
  перцентиль запаздывания данных);
- позиция считается без округления до пикселя.

Поэтому автобусы движутся непрерывно и с реальной скоростью.

Карта векторная: MapLibre GL, тайлы и стиль Liberty от OpenFreeMap. Подписи переведены
на русские названия, дороги перекрашены в нейтральные тона, чтобы янтарная и красная подсветка риска не
сливалась с магистралями. Без доступа к тайлам карта работает на пустом фоне:
маршруты, ТС и участки риска всё равно отображаются.

## Деградация

| Сбой | Поведение |
|---|---|
| Обрыв NDTP-соединения | терминал помечается отключённым, ТС показывается по последнему состоянию; эмулятор/replayer переподключаются автоматически |
| Нет данных от ТС > 2 мин | статус `stale`, прогноз строится по последнему состоянию и профилю, флаг `degraded` |
| ML-ядро недоступно | backend переходит на встроенный fallback (сжатое текущее отклонение + профиль остановки), каждые 10 c пробует вернуться |
| Перемотка потока назад | состояние парка сбрасывается, новая сессия |
| Мусор/битый CRC в потоке | кадр пропускается, ресинхронизация по сигнатуре `0x7E7E`, счётчики ошибок в `/api/health` |
